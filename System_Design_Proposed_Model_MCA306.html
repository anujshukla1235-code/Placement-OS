1. System Overview & Architectural Scope

Placement OS is an enterprise-grade, multi-tenant B2B Software-as-a-Service (SaaS) platform engineered to unify, automate, and algorithmically optimize the end-to-end campus placement lifecycle across higher education institutions. The system integrates four specialized user roles — Students, Corporate Recruiters (Companies), College Placement Authorities (TPOs), and Platform Super-Administrators — operating under strict row-level tenant isolation, rate-limited API access, and granular Role-Based Access Control (RBAC).

The core computational pillars of Placement OS encompass:

  1. Dual-Engine AI ATS Resume Screening: Integrating mathematical n-gram TF-IDF vector space modeling with NLP skill-dictionary parsing and Generative AI qualitative feedback.
  2. Cryptographic Blockchain-Inspired Offer Verification: SHA-256 sequential hash-chaining binding student, company, and remuneration credentials with public QR validation.
  3. Supervised Machine Learning Placement Predictor: Logistic Regression classification model calculating probability-of-placement based on academic and skill features.
  4. Multi-Channel Asynchronous Event Pipeline: Celery-Redis task workers dispatching transactional emails, in-app alerts, and automated WhatsApp notifications.

7. Core Mathematical Formulations & Algorithms

7.1 Hybrid ATS Resume Scoring Algorithm

$$\text{ATS Score} = \Big(0.50 \times \mathcal{S}_{\text{cosine}} \times 100\Big) + \Big(0.35 \times \mathcal{R}_{\text{skills}} \times 100\Big) + \Big(0.15 \times \mathcal{Q}_{\text{qual}} \times 100\Big)$$
$$\text{Where: } \mathcal{S}_{\text{cosine}} = \frac{\mathbf{v}_{\text{resume}} \cdot \mathbf{v}_{\text{job}}}{\|\mathbf{v}_{\text{resume}}\| \|\mathbf{v}_{\text{job}}\|}, \quad \mathcal{R}_{\text{skills}} = \frac{|\mathcal{K}_{\text{resume}} \cap \mathcal{K}_{\text{job}}|}{|\mathcal{K}_{\text{job}}|}, \quad \mathcal{Q}_{\text{qual}} = \begin{cases} 1.0 & \text{if branch eligible} \\ 0.5 & \text{otherwise} \end{cases}$$
ALGORITHM: CalculateHybridATSScore INPUT: resume_pdf_stream, job_record, student_profile OUTPUT: { ats_score: Float, matched_skills: List, missing_skills: List, ai_feedback: String } BEGIN // Step 1: Text extraction and validation raw_text = ExtractTextWithFallback(resume_pdf_stream) IF raw_text IS EMPTY THEN RETURN { ats_score: 0.0, error: "Unreadable PDF" } // Step 2: N-gram TF-IDF Vector Space Modeling vectorizer = TfidfVectorizer(ngram_range=(1, 2), stop_words='english') tfidf_matrix = vectorizer.fit_transform([raw_text, job_record.description]) cosine_sim = cosine_similarity(tfidf_matrix[0:1], tfidf_matrix[1:2])[0][0] // Step 3: NLP Dictionary Skill Extraction extracted_skills = MatchSkillDictionary(raw_text, SKILLS_DICTIONARY) required_skills = job_record.required_skills matched_skills = extracted_skills INTERSECT required_skills missing_skills = required_skills DIFFERENCE extracted_skills skill_ratio = LENGTH(matched_skills) / MAX(LENGTH(required_skills), 1) // Step 4: Qualification & Cutoff Computation qual_factor = (student_profile.branch IN job_record.eligibility_branch) ? 1.0 : 0.5 // Step 5: Final Weighted Aggregation composite_ats = (0.50 * cosine_sim * 100) + (0.35 * skill_ratio * 100) + (0.15 * qual_factor * 100) final_score = CLAMP(ROUND(composite_ats, 2), 0.0, 100.0) // Step 6: Asynchronous Generative AI Feedback (Gemini API) feedback_text = GenerateGeminiFeedback(raw_text, matched_skills, missing_skills) RETURN { ats_score: final_score, matched_skills, missing_skills, ai_feedback: feedback_text } END

7.2 Sequential Hash-Chain Generation & Integrity Verification Algorithm

ALGORITHM: ComputeSequentialOfferHash INPUT: candidate_name, company_name, designation, salary_ctc, joining_date, offer_text OUTPUT: { sha256_digest: String, previous_hash: String } BEGIN last_offer = OfferLetter.objects.order_by('-issued_at').first() previous_hash = (last_offer != NULL) ? last_offer.hash_sha256 : REPEAT("0", 64) payload_string = CONCAT_WITH_PIPE( candidate_name, company_name, designation, salary_ctc, joining_date, offer_text, previous_hash ) sha256_digest = SHA256(UTF8_ENCODE(payload_string)).HEX_DIGEST() RETURN { sha256_digest, previous_hash } END

9. Multi-Layered Security Architecture

  1. Layer 1 — Transport Security: Strict HTTPS/TLS enforcement, HSTS (31,536,000s), Secure & HttpOnly Cookie flags, X-Frame-Options: DENY.
  2. Layer 2 — Authentication & Token Lifecycle: SimpleJWT stateless tokens (30-min access, 1-day refresh) with automated rotation and token blacklisting.
  3. Layer 3 — Two-Factor MFA Hardening: Mandatory email OTP for logins with 2-minute expiration and 3-attempt brute-force invalidation.
  4. Layer 4 — Role-Based Access Control: Strict permission classes (IsAuthenticated, IsCompany, IsCollege, IsAdmin) on all DRF viewsets.
  5. Layer 5 — Logical Multi-Tenancy Isolation: TenantMiddleware resolves tenant context per-request, enforcing row-level database QuerySet isolation.
  6. Layer 6 — Tenant-Scoped Rate Throttling: Custom TenantRateThrottle keys buckets by Tenant ID, insulating tenants from noisy-neighbor quota exhaustion.
  7. Layer 7 — Data Integrity & Auditability: SHA-256 chained hashes for digital offers, immutable ApplicationAuditLog tracking all status transitions.
  8. Layer 8 — Centralized Observability: Structured JSON logging via python-json-logger, PII-sanitized error monitoring via Sentry.
